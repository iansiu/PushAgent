> **Статус production-сборки:** В production-сборку QiuyuRemote для App Store не входят интеграция ~~yt-dlp~~ и управление Cookie. Разделы про ~~yt-dlp~~ ниже сохранены для внутренних сборок и существующих развёртываний PushAgent.

QiuyuRemote можно использовать как прямой менеджер загрузок или вместе с Push Agent для уведомлений и ~~yt-dlp~~.

## Базовый режим и режим Agent

Без Push Agent QiuyuRemote все равно может напрямую управлять существующими qBittorrent, Transmission и aria2. Приложение подключается к Web API или RPC endpoint этих сервисов.

Push Agent нужен только для серверных фоновых функций.

| Функция | Требуется Push Agent |
| --- | --- |
| Управление задачами qBittorrent, Transmission или aria2 | Нет |
| Добавление, пауза, продолжение, удаление, лимиты и просмотр деталей qBittorrent, Transmission или aria2 | Нет |
| Просмотр и воспроизведение файлов через WebDAV | Нет, но WebDAV нужно настроить отдельно |
| Локальные офлайн-загрузки | Нет |
| Уведомления о локальных офлайн-загрузках | Нет |
| Уведомления о завершении или ошибке удаленной загрузки | Да |
| Уведомления о задаче без данных длительное время | Да |
| Уведомления об отключении или восстановлении сервера загрузок | Да |
| <del>Загрузки yt-dlp</del> | <del>Да</del> |
| <del>Управление Cookie для yt-dlp</del> | <del>Да</del> |
| <del>Отправка media URL из другого приложения в QiuyuRemote для удаленной загрузки yt-dlp</del> | <del>Да</del> |

## Бесплатная версия и Pro

QiuyuRemote можно скачать и использовать бесплатно. Бесплатная версия подходит для базового удаленного управления загрузками: вы можете подключить существующий сервер qBittorrent, Transmission или aria2, просматривать задачи, добавлять загрузки, ставить их на паузу, возобновлять и удалять.

Pro предназначен для пользователей, которым нужны более полные возможности удаленного управления. После перехода на Pro доступны:

- загрузки ~~yt-dlp~~
- управление Cookie для ~~yt-dlp~~ на сайтах, где требуется вход
- удаленные уведомления о загрузках через Push Agent
- синхронизация профилей серверов и настроек приложения через iCloud
- Offline Library и управление офлайн-задачами
- воспроизведение WebDAV и доступ к файлам
- уведомления о завершении загрузки
- расширенные настройки серверов
- серверы ~~yt-dlp~~ и смешанные конфигурации aria2/qBittorrent/Transmission вместо одного типа прямого сервиса загрузок

Статус Pro и сопряжение Push Agent разделены. Покупка Pro не подключает Agent автоматически, а сопряжение Agent не доказывает наличие покупки Pro.

## Серверы

Если серверов еще нет, на первом экране отображается вход для добавления сервера.

После добавления хотя бы одного сервера добавление нового сервера находится в меню сервера.

- На iPhone нажмите имя сервера вверху, чтобы переключить сервер. Долгое нажатие на имя сервера открывает меню New, Edit и Delete.
- На iPhone горизонтальные карточки серверов также переключают серверы. Долгое нажатие на карточку позволяет изменить или удалить сервер.
- На iPad или Mac нажмите имя сервера для переключения. На iPad долго нажмите имя сервера, а на Mac нажмите правой кнопкой по имени сервера, чтобы открыть New, Edit и Delete.
- В свернутой боковой панели используйте кнопку плюс под кнопкой настроек.
- Правый клик или долгое нажатие по строке/иконке сервера позволяет изменить или удалить этот сервер.

Удаление сервера из QiuyuRemote удаляет только сохраненный профиль подключения в приложении. Оно не удаляет задачи или файлы на сервере загрузок.

Поддерживаемые типы серверов:

- Transmission: подключение к Transmission RPC.
- aria2: подключение к aria2 JSON-RPC.
- qBittorrent: подключение к qBittorrent Web UI API.
- ~~yt-dlp~~: подключение к API PushAgent `v1/ytdlp`. ~~yt-dlp~~ выполняется на сервере, а не на телефоне или Mac.

## Добавление загрузок

Кнопка добавления на главном экране создает новую задачу.

- qBittorrent и Transmission подходят для magnet links и `.torrent` файлов.
- aria2 может обрабатывать обычные HTTP/HTTPS URL файлов, metalink, magnet и torrent, в зависимости от конфигурации aria2.
- ~~yt-dlp~~ принимает HTTP/HTTPS URL страниц медиа, например YouTube, TikTok, Bilibili, Instagram, X, Threads и другие сайты, поддерживаемые ~~yt-dlp~~.

На iPhone и iPad можно отправить URL из другого приложения в QiuyuRemote через системное меню Share. Для ~~yt-dlp~~ сначала добавьте и подключите сервер ~~yt-dlp~~ PushAgent. Из-за ограничений iOS отправка может завершиться только после открытия QiuyuRemote.

## URL Scheme и Shortcuts

QiuyuRemote регистрирует URL Scheme `qiuyuremote://`, чтобы Shortcuts или другое приложение могли отправить ссылку на загрузку.

Базовые примеры:

```text
qiuyuremote://addTask?url=https%3A%2F%2Fexample.com%2Ffile.zip
qiuyuremote://addTask?type=aria2&url=https%3A%2F%2Fexample.com%2Ffile.zip
qiuyuremote://addTask?type=ytdlp&url=https%3A%2F%2Fwww.youtube.com%2Fwatch%3Fv%3DVIDEO_ID
```

`addTask` по умолчанию использует текущий выбранный сервер. Добавьте `type=aria2`, `type=qbit`, `type=transmission` или `type=ytdlp`, чтобы использовать первый сервер указанного типа. Добавьте `server=<имя сервера или UUID>`, чтобы выбрать конкретный сохраненный сервер.

`autoAdd=true` используется по умолчанию. Если указать `autoAdd=false`, QiuyuRemote откроет окно Add Download с уже заполненным URL, чтобы можно было настроить параметры перед отправкой.

Обычные правила совместимости остаются в силе:

- qBittorrent и Transmission принимают magnet-ссылки или `.torrent` URL.
- aria2 принимает обычные URL файлов, magnet и torrent, в зависимости от конфигурации aria2.
- ~~yt-dlp~~ принимает HTTP/HTTPS URL страниц медиа и требует настроенный сервер ~~yt-dlp~~ PushAgent.

Для Shortcuts также поддерживается `x-callback-url`:

```text
qiuyuremote://x-callback-url/addTask?type=aria2&url=https%3A%2F%2Fexample.com%2Ffile.zip&x-success=shortcuts%3A%2F%2F&x-error=shortcuts%3A%2F%2F
```

При успехе `x-success` получает `count`, `gid` и `gids`. Для одной отправленной задачи `count` равен `1`. Так как разные сервисы загрузки по-разному возвращают ID задачи, `gid` и `gids` сейчас пустые. Если в будущем конкретный сервис сможет надежно возвращать ID, будут добавлены точные значения. При ошибке `x-error` получает `errorCode` и `errorMessage`.

Всегда URL-encode значения `url`, `x-success` и `x-error`, особенно если сама ссылка загрузки содержит `?`, `&` или не-ASCII символы.

## Список задач

Порядок по умолчанию оптимизирован для обычного использования.

- Активные или загружающиеся задачи отображаются выше.
- Завершенные задачи идут после активных.
- Новые завершенные задачи отображаются выше старых завершенных задач.
- Если вручную сортировать по столбцу, сортировка столбца имеет приоритет над группировкой по умолчанию.

На iPad и Mac ширину столбцов можно менять перетаскиванием границы в заголовке таблицы. Столбец Name можно сделать намного шире для длинных имен задач.

Для задач ~~yt-dlp~~ скрываются torrent-only поля, например скорость отдачи, объем отдачи, seeds, leechers и ratio.

## Соответствие статусов задач

В списке задач QiuyuRemote показывает нормализованный статус приложения. Если сервис загрузки возвращает исходный статус, приложение по возможности сохраняет и его. App учитывает нормализованный статус, исходный статус, прогресс, скорость передачи и уведомления автоматических правил. Поэтому завершенный torrent, остановленный правилом ratio или idle, может отображаться как Stopped с пояснением, а не просто как Complete.

| Сервис | Статус сервиса или условие | Статус в App |
| --- | --- | --- |
| qBittorrent | `error`, `missingFiles` | Error |
| qBittorrent | `pausedUP`, `stoppedUP`, `stalledUP`, `queuedUP` | Complete; при уведомлении автоматического правила может отображаться как Stopped |
| qBittorrent | значения с `paused`, или `stoppedDL` | Paused |
| qBittorrent | значения с `queued` | Waiting |
| qBittorrent | значения с `checking`, `metadata`, `allocating`; также `filesChecked`, `metadataReceived` | Checking или Processing |
| qBittorrent | значения с `uploading` или `forcedUP` | Seeding |
| qBittorrent | значения с `stalled` | Stalled |

| qBittorrent | `moving` | Moving |

| Transmission | `0` | Stopped; если прогресс завершен, QiuyuRemote считает задачу Complete, кроме случаев с уведомлением автоматического правила |

## Действия с задачами

Выберите задачу, чтобы открыть детали. Долгое нажатие или правый клик по задаче открывает меню действий.

- Продолжить или поставить на паузу
- Удалить
- Скопировать имя, исходную ссылку или путь
- Установить лимит скорости загрузки или отдачи, если сервис поддерживает
- Установить ratio, если сервис поддерживает
- Force recheck, если сервис поддерживает

Если задача qBittorrent или Transmission остановлена автоматическим правилом, при продолжении появляется выбор.

- Continue: сохранить текущее правило. Задача может снова остановиться автоматически.
- Disable Rules and Continue: отключить только правило, которое остановило эту задачу, и продолжить.
- Not Now: оставить текущее состояние.

Для aria2 продолжение проще. Если aria2 сохранил достаточно информации о задаче, QiuyuRemote попросит aria2 продолжить или заново добавить задачу. Для завершенных задач Resume отображается как недоступный.

При удалении Remove Task Only сохраняет загруженные файлы. Remove Task And Downloaded Files просит сервер удалить и локальные данные, если сервис это поддерживает. aria2 RPC может удалить задачу и историю, но не может надежно удалить завершенные файлы с диска.

## Файлы, WebDAV и офлайн-библиотека

Если сервис загрузок возвращает информацию о файлах, детали задачи показывают список файлов.

WebDAV является необязательным. Если каталог загрузок открыт через WebDAV, настройте WebDAV глобально или для отдельного сервера. QiuyuRemote сможет просматривать файлы и передавать URL воспроизведения внешним плеерам.

Офлайн-библиотека хранится только на текущем устройстве. Офлайн-файлы не синхронизируются через iCloud. Уведомления о локальных офлайн-загрузках отправляются самим QiuyuRemote и не требуют Push Agent.

Если файл уже есть на диске, но еще не виден в WebDAV, обновите WebDAV provider, например OpenList, или дождитесь обновления индекса/кэша.

## Внешние плееры

Когда включен параметр Allow third-party players, QiuyuRemote может передавать ссылки воспроизведения видео установленным плеерам с поддерживаемыми URL scheme.

Для удаленного или WebDAV-воспроизведения быстрые действия сейчас поддерживают:

- iPhone и iPad: nPlayer, Infuse, VidHub, Fileball, SenPlayer и Forward.
- Mac Catalyst: IINA, Infuse, VidHub, SenPlayer, nPlayer, Fileball и Forward.

QiuyuRemote сначала проверяет, какие плееры установлены, и только затем показывает быстрые действия. Для приватных WebDAV или OpenList файлов приложение использует прямую ссылку, когда она доступна, либо временную локальную proxy-ссылку, если она нужна плееру. Названия TMDB и ссылки на субтитры передаются только тогда, когда URL scheme выбранного плеера это поддерживает.

Быстрые действия для локальных файлов Offline Library сейчас поддерживаются только в Mac Catalyst. На iPhone и iPad используйте Open with Other Player или системное меню общего доступа для локальных offline-файлов.

## Уведомления

Разрешение системных уведомлений управляется iOS, iPadOS или macOS.

- Уведомления о локальных офлайн-загрузках отправляет QiuyuRemote.
- Уведомления о задачах qBittorrent, Transmission и aria2 требуют запущенный и спаренный Push Agent на сервере загрузок.
- Уведомления о задачах ~~yt-dlp~~ также приходят от Push Agent.
- Тестовое уведомление Push Relay проверяет только возможность этого устройства получать APNs через Push Relay. Оно не доказывает, что серверный Push Agent спарен или запущен.

Чтобы получать уведомления об удаленных загрузках:

1. Включите уведомления в QiuyuRemote.
2. Создайте код pairing для Agent в QiuyuRemote.
3. Откройте веб-страницу PushAgent на сервере.
4. Введите код pairing и спарьте Agent.
5. Оставьте PushAgent запущенным на сервере.

## <del>yt-dlp и Cookie</del>

Загрузки ~~yt-dlp~~ выполняются на PushAgent. QiuyuRemote отправляет URL и показывает состояние задачи, возвращенное Agent.

Управление Cookie изолировано для каждого сервера ~~yt-dlp~~ PushAgent. Cookie загружаются напрямую на выбранный PushAgent и хранятся на этом сервере. Они не отправляются в Push Relay, не синхронизируются через iCloud и не записываются в журналы.

Используйте файлы `cookies.txt` в формате Netscape, экспортированные из браузера. Cookie равнозначны учетным данным входа на сайт, поэтому не передавайте их другим.

В настольных браузерах, если браузер поддерживает это, расширение `Get cookies.txt LOCALLY` может экспортировать стандартный файл Cookie в формате Netscape. На iOS можно использовать Microsoft Edge с расширением `Cookie-Editor`: в настройках расширения выберите Export Format `Netscape`, скопируйте Cookie текущего сайта в буфер обмена, затем запустите Shortcut `Create a new cookie file`: `https://www.icloud.com/shortcuts/21cc1f1ace944cb6aec28c25e833510f`. Shortcut создаст Cookie-файл в `On My iPhone/Downloads`, после чего его можно напрямую импортировать в QiuyuRemote.

Для каждой задачи ~~yt-dlp~~ Cookie выбираются в таком порядке: cookies path, явно заданный для задачи; Cookie соответствующего сайта, импортированные в QiuyuRemote; fallback `cookiesPath` из `config.json` PushAgent. Значит, сайтный Cookie, импортированный в приложении, имеет более высокий приоритет, чем файл из конфига.

Срок действия Cookie, показанный в QiuyuRemote, является только оценкой по содержимому Cookie-файла. Реальная доступность может измениться раньше из-за выхода из аккаунта, смены пароля, проверок безопасности аккаунта, изменения IP/региона сервера, принудительной инвалидизации сайтом, rate limit или изменений extractor в ~~yt-dlp~~.

Если YouTube или другой сайт требует вход или Cookie, импортируйте или обновите Cookie соответствующего сайта в Cookie Management. Для YouTube также могут потребоваться обновление ~~yt-dlp~~, ffmpeg и JavaScript runtime, например Deno, для текущих signature challenges.

## Синхронизация и приватность

Профили серверов и настройки приложения могут синхронизироваться через iCloud. Пароли и token используют iCloud Keychain. Загруженные файлы и элементы офлайн-библиотеки не синхронизируются.

Если включена защита приватности, Face ID, Touch ID или пароль устройства обрабатываются системным интерфейсом Apple.

## Диагностика

- Если прямой сервер загрузок не подключается, проверьте адрес, порт, путь, SSL, имя пользователя, пароль, token и доступность сервиса из текущей сети.
- Для qBittorrent используйте базовый URL Web UI. Не добавляйте `/api/v2` вручную.
- Для Transmission используйте RPC endpoint, обычно `/transmission/rpc`.
- Для aria2 используйте JSON-RPC endpoint и token, если настроен secret.
- Для ~~yt-dlp~~ подключайтесь к endpoint PushAgent `v1/ytdlp`. Если в Agent задан `apiKey`, введите тот же API Key в приложении.
- Если удаленные уведомления не приходят, проверьте разрешение уведомлений, Focus mode, регистрацию Push Relay, pairing Agent и запущен ли PushAgent.
- Если WebDAV не воспроизводит или не находит файл, проверьте, что путь WebDAV соответствует реальному каталогу загрузок, и обновите WebDAV service.
